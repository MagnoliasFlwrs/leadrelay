# Техническое задание
## Сервис маршрутизации лидов Instagram и TikTok в Telegram

| | |
|---|---|
| Код | ТЗ-LR-001 |
| Версия | 1.0 |
| Дата | 25 сентября 2026 |
| Статус | Черновик к согласованию |
| Рабочее имя продукта | LeadRelay |

Документ описывает фронтенд (админ-панель) и бэкенд сервиса, который принимает рекламные заявки из Instagram Lead Ads и TikTok Lead Generation, хранит их в единой таблице и пересылает в выбранный Telegram-бот и Telegram-канал в зависимости от рекламной кампании.

Контекст заказчика: автоцентры Dongfeng, формы с выбором ближайшего дилера, типом обращения (физлицо / юрлицо), именем и телефоном.

---

## 1. Цель и границы

### 1.1. Цель

Собрать все заявки с рекламы Instagram и TikTok в одном сервисе, показать их сотруднику в таблице и автоматически отправить в Telegram тому боту и в тот канал, которые привязаны к конкретной внутренней кампании.

### 1.2. Входит в первую версию

- Приём вебхуков Instagram и TikTok и сохранение лида.
- Таблица запросов с фильтрами, карточкой лида и повторной отправкой в Telegram.
- Создание / редактирование / удаление (архивация) рекламных кампаний.
- Создание / редактирование / удаление Telegram-ботов и Telegram-каналов.
- В форме кампании — выбор бота и канала; шаблон сообщения; тестовая отправка.
- Админ-панель с авторизацией (роли администратор и оператор).
- Очередь отправки в Telegram с ретраями и статусом доставки.

### 1.3. Вне скоупа v1

- Создание и управление рекламой внутри Meta / TikTok Ads Manager.
- CRM, коллтрекинг, скоринг, распределение между менеджерами.
- WhatsApp, email, SMS как каналы доставки.
- Мультитенантность с изоляцией данных нескольких юридических лиц.
- Публичный кабинет дилера без роли сотрудника сервиса.

### 1.4. Ключевое правило

Лид никогда не теряется: если кампания не сопоставлена или Telegram недоступен, заявка сохраняется в таблице со статусом «не распределён» или «ошибка доставки». Повторная отправка доступна из админки.

## 2. Глоссарий

| Термин | Значение в этом ТЗ |
|---|---|
| Лид / запрос | Заявка человека с рекламной формы: имя, телефон, дилер, служебные поля объявления |
| Кампания (внутренняя) | Правило маршрутизации в LeadRelay: какие объявления куда слать в Telegram |
| Рекламная кампания (внешняя) | Кампания в Ads Manager Instagram / TikTok; её идентификатор используется для сопоставления |

| Канал | Telegram-канал, супергруппа или чат. Идентификатор — `chat_id` |
| Маршрут | Связка «внутренняя кампания → бот + канал + шаблон» |
| Lead status | Статус заявки на стороне рекламной платформы |
| Delivery status | Статус доставки в Telegram: `queued`, `sent`, `failed`, `skipped` |
| Route status | Результат сопоставления: `matched` или `unmatched` |

## 3. Роли

| Роль | Права |
|---|---|
| Администратор | Полный доступ: боты, каналы, кампании, лиды, повторная отправка, настройки интеграций, сотрудники |
| Оператор | Таблица и карточка лидов, фильтры, экспорт, повторная отправка. Без удаления ботов и просмотра токенов |
| Система | Приём вебхуков, нормализация, сопоставление кампании, очередь Telegram |

```
Instagram Lead Ads          TikTok Lead Generation
        │                            │
        │ webhook                    │ webhook / periodic sync
        └────────────┬───────────────┘
                     ▼
              LeadRelay API
         нормализация · маршруты · REST
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
     PostgreSQL    Redis     Админ-панель
     лиды,          очередь    React SPA

                 Telegram Bot API
                        │
```

Админ-панель ходит только в LeadRelay API. Браузер сотрудника не обращается к Meta, TikTok и Telegram напрямую.

### 4.1. Рекомендуемый стек

| Слой | Технология | Зачем |
|---|---|---|
| Админ-панель | React + TypeScript | Таблица лидов, CRUD кампаний / ботов / каналов |
| API | NestJS (Node.js) или FastAPI (Python) | Вебхуки, REST, авторизация, очередь |
| БД | PostgreSQL | Лиды, кампании, боты, каналы, пользователи, журнал доставок |
| Очередь | Redis + BullMQ / RQ | Ретраи Telegram, идемпотентная обработка вебхуков |
| Инфра | Docker Compose, HTTPS, секреты в env | Локальный запуск и стенд |

Требования привязаны к сущностям и контрактам, а не к фреймворку. Обязательны PostgreSQL, очередь с ретраями, раздельное хранение токенов Meta / TikTok / Telegram.

## 5. Потоки данных

1. Человек отправляет форму в Instagram или TikTok.
2. Платформа вызывает сервис. Подпись проверяется. HTTP 200 возвращается сразу после постановки в обработку (лимит ожидания вебхука у платформ короткий).
3. Лид пишется в таблицу. Дубль по `(platform, external_lead_id)` не создаётся.
4. Подбирается активная внутренняя кампания: бот + канал.
5. Шаблон рендерится и уходит в канал. У лида обновляется статус доставки.

### FR-01. Единая точка входа

HTTPS-эндпоинты:

- `GET/POST /webhooks/instagram`
- `POST /webhooks/tiktok`

Лиды, загруженные оператором из CSV, проходят тот же конвейер нормализации и маршрутизации.

### FR-02. Идемпотентность

Повтор вебхука с тем же внешним id не создаёт дубль. Уникальность: `(platform, external_lead_id)`. Повтор может обновить служебные поля платформы. Telegram не отправляется второй раз, если `delivery_status = sent`.

### FR-03. Сопоставление кампании

После сохранения лид сопоставляется с внутренней кампанией по правилам раздела 10. Если совпадений нет — служебная кампания «Нераспределённые», `route_status = unmatched`, в Telegram не уходит.

Основной рабочий экран админки. Набор колонок зависит от платформы: у Instagram и TikTok разные поля форм. Фиксируются оба состава и общая проекция для сводного вида.

### 6.1. Сводные колонки (все платформы)

| Поле | Источник | Описание |
|---|---|---|
| `created_at` | сервис / платформа | Время поступления, часовой пояс `Europe/Moscow` |
| `platform` | сервис | `instagram` \| `tiktok` |
| `external_lead_id` | платформа | id лида Instagram или TikTok Lead ID |
| `name` | форма | `полное_имя` / `Name` |
| `phone` | форма | номер телефона, нормализованный в E.164 |
| `dealer` | форма | автоцентр / `Dealer` |
| `person_type` | Instagram | физлицо / юрлицо; у TikTok пусто, если поля нет в форме |
| `campaign_name` | платформа | `campaign_name` / `Group Ads` |
| `ad_name` | платформа | `ad_name` / `Ad name` |
| `lead_status` | платформа | `lead_status` / `TikTok Lead Status` |
| `route_status` | сервис | `matched` \| `unmatched` |
| `delivery_status` | сервис | `queued` \| `sent` \| `failed` \| `skipped` |
| `internal_campaign` | сервис | название внутренней кампании LeadRelay |

### FR-10. Фильтры и поиск

Фильтры: период, платформа, внутренняя кампания, дилер, `delivery_status`, `route_status`. Поиск по имени, телефону, внешнему id, названию объявления. Пагинация. Сортировка по дате по убыванию. Экспорт CSV текущего фильтра.

Переключатель вида таблицы:

- **Все** — сводные колонки.
- **Instagram** — состав раздела 7.
- **TikTok** — состав раздела 8.

### FR-11. Карточка лида

По клику: все исходные поля платформы, сырой JSON, сопоставленная кампания, бот, канал, лог попыток Telegram, кнопка «Отправить снова».

### FR-12. Пустые и ошибочные состояния

Нет лидов — пояснение и ссылка на настройки вебхуков. Ошибка загрузки — сообщение и повтор. Невалидный телефон сохраняется как есть, в карточке пометка «не нормализован», в Telegram уходит исходная строка.

## 9. Доставка в Telegram

Для каждой внутренней кампании администратор выбирает бота и канал. Сообщение отправляется Bot API методом `sendMessage` от имени выбранного бота в `chat_id` канала. Бот должен быть администратором канала с правом публикации.

### FR-40. Шаблон сообщения

У кампании свой шаблон. Плейсхолдеры:

`{name}` `{phone}` `{dealer}` `{person_type}` `{platform}` `{campaign_name}` `{ad_name}` `{form_name}` `{lead_status}` `{created_at}` `{external_lead_id}` `{select}` `{data}`

Незаполненные плейсхолдеры удаляются вместе с подписью строки.

Шаблон по умолчанию:

```
🆕 Новый лид · {platform}

Имя: {name}
Телефон: {phone}
Автоцентр: {dealer}
Тип: {person_type}

Кампания: {campaign_name}
Объявление: {ad_name}
Форма: {form_name}
Статус: {lead_status}
Время: {created_at}
ID: {external_lead_id}
```

### FR-41. Очередь и ретраи

Отправка асинхронная. 5 попыток с паузами 5 с, 20 с, 1 мин, 5 мин, 15 мин. Учитывается HTTP 429 `Retry-After`. После исчерпания: `delivery_status = failed`, ошибка в логе попыток, лид остаётся в таблице. Оператор нажимает «Отправить снова».

### FR-42. Проверка бота и канала

При создании / редактировании бота сервис вызывает `getMe`. При привязке канала — `getChat` и проверку права отправки. Невалидный токен или канал без прав нельзя сохранить как активный.

## 10. Кампании и правила маршрутов

Внутренняя кампания — правило «какие лиды куда слать». Это не копия Ads Manager, а маршрутизатор.

### 10.1. Поля кампании

| Поле | Обязательно | Описание |
|---|---|---|
| `name` | да | Человекочитаемое имя в админке |
| `status` | да | `active` \| `paused` \| `archived` |
| `platform` | да | `instagram` \| `tiktok` \| `both` |
| `telegram_bot_id` | да, если `active` | Кто отправляет |
| `telegram_channel_id` | да, если `active` | Куда отправляет |
| `message_template` | нет | Переопределение шаблона |
| `match_rules` | да | Набор условий сопоставления |
| `priority` | да | Целое, больше — важнее; по умолчанию 100 |
| `notes` | нет | Комментарий для операторов |

### 10.2. Правила сопоставления

Кампания срабатывает, если платформа лида входит в `platform` и выполнено хотя бы одно включённое условие (логика OR внутри кампании). Если подошло несколько кампаний — берётся с наивысшим `priority`, при равенстве более специфичная (больше заполненных идентификаторов), затем более новая.

| Условие | Платформа | С чем сравнивать |
|---|---|---|
| `instagram_campaign_id` | Instagram | `campaign_id` лида |
| `instagram_adset_id` | Instagram | `adset_id` |
| `instagram_ad_id` | Instagram | `ad_id` |
| `instagram_form_id` | Instagram | `form_id` |
| `tiktok_group_ads` | TikTok | `Group Ads` (точное совпадение строки) |
| `tiktok_ad_name` | TikTok | `Ad name` |
| `tiktok_name_ads` | TikTok | `Name Ads` |

### FR-50. CRUD кампаний

Создание, редактирование, удаление, пауза. Физическое удаление запрещено, если по кампании уже есть лиды: только архивация (`status = archived`), лиды сохраняют ссылку. Нельзя активировать кампанию без бота и канала.

### FR-51. CRUD ботов

Поля: имя, токен, `is_active`. После `getMe` сохраняются `username` и `telegram_id`. Токен в API наружу не отдаётся, только маска (`123456:****abcd`). Удаление: если бот привязан к активной кампании — отказ 409 с перечнем кампаний.

### FR-52. CRUD каналов

Поля: имя, `chat_id`, username (`@channel`), комментарий, `is_active`. Проверка, что выбранный бот может писать в канал. Один канал можно использовать в нескольких кампаниях и с разными ботами, если оба бота — администраторы канала.

## 11. Админ-панель

Закрытый веб-интерфейс. Десктоп — основная рабочая ширина. Мобильный — просмотр лидов и статусов; широкие таблицы со горизонтальным скроллом.

| Экран | Содержание |
|---|---|
| Вход | Email / пароль, восстановление пароля |
| Дашборд | Лиды за сегодня и 7 дней, ошибки доставки, нераспределённые, последние 10 заявок |
| Запросы | Таблица, фильтры, карточка, экспорт, повторная отправка |
| Кампании | Список маршрутов, форма с выбором бота и канала |
| Боты | Список, добавление токена, проверка `getMe`, деактивация |
| Каналы | Список, `chat_id`, проверка доступа ботом |
| Сотрудники | Приглашение администратора и оператора, деактивация |
| Интеграции | Секреты Meta и TikTok, URL вебхуков, Verify Token, тест-кнопка |

### FR-60. Выбор бота и канала в кампании

В форме кампании обязательные селекты «Telegram-бот» и «Telegram-канал» из активных сущностей. Предпросмотр шаблона на тестовых данных. Кнопка «Отправить тест» пишет в канал контрольное сообщение.

### FR-61. Журнал действий

Кто создал / изменил / архивировал кампанию, бота, канал. Просмотр токена бота не логируется целиком. Вход и смена интеграционных секретов пишутся в аудит-лог.

`payload` — полный ответ платформы. `extra_fields` — кастомные вопросы формы вне фиксированной схемы. Колонки `name` / `phone` / `dealer` денормализованы для фильтров.

Индексы: `(platform, created_at desc)`, `(phone)`, `(campaign_id)`, `(delivery_status, created_at)`, `(route_status)`.

### FR-70. Контракт ошибок

JSON `{ "error": { "code": "...", "message": "..." } }`.

HTTP: 400, 401, 403, 404, 409, 422, 429.

- 409 — удаление бота, занятого активной кампанией.
- 422 — невалидный токен Telegram или неполный `match_rules` у активной кампании.

## 16. Критерии приёмки

1. Тестовый лид Instagram с полным набором полей раздела 7 появляется в таблице и в Telegram-канале, указанном у кампании.
2. Тестовый лид TikTok с полями Name, Phone, Dealer, Group Ads, Ad name, TikTok Lead ID — аналогично.
3. Смена бота или канала у кампании влияет только на новые лиды; старые записи не переписываются.
4. Повтор вебхука не создаёт второй лид и не шлёт второе сообщение, если первое уже `sent`.
5. Неизвестная рекламная кампания: лид в таблице, `route_status = unmatched`, в Telegram не уходит.
6. Удаление бота, занятого активной кампанией, блокируется. Архивация кампании с лидами сохраняет историю.
7. Невалидный токен бота нельзя сохранить как активный. Ошибка доставки видна в карточке и на дашборде.
8. Оператор без прав администратора не видит токены и не удаляет ботов / каналы.
9. CRUD ботов, каналов и кампаний доступен из админки: создание, редактирование, удаление / архивация.
10. В кампании обязательно выбираются Telegram-бот и Telegram-канал.

## 17. Зафиксированные решения v1

- Часовой пояс: `Europe/Moscow`.
- Органические заявки (`is_organic = true`) принимаются и маршрутизируются так же, как рекламные.
- Несколько внутренних кампаний на один внешний `campaign_id` допустимы — побеждает `priority`.
- Ручная смена дилера в карточке лида в v1 не нужна.
- Физическое удаление лидов в v1 не предусмотрено.
