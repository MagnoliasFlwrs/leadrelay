# Техническое задание
## Сервис маршрутизации лидов Instagram и TikTok в Telegram

| | |
|---|---|
| Код | ТЗ-LR-001 |
| Версия | 1.2 |
| Дата | 25 сентября 2026 |
| Статус | Черновик к согласованию |
| Рабочее имя продукта | Notify 2.0 |
| Роли | Админ, сотрудник |

Документ описывает фронтенд и бэкенд сервиса, который принимает рекламные заявки из Instagram Lead Ads и TikTok Lead Generation, кладёт их в таблицу и пересылает в выбранный Telegram-бот и Telegram-группу в зависимости от рекламной кампании.

Контекст: автоцентры Dongfeng. Текущий общий список заявок (фильтры + таблица на синем фоне) требует редизайна. Дашборд — версия 2.

### Что изменилось в 1.2

- API опирается на существующий [Notification_APS](https://notify-api.aps.by/docs), заголовок `x-auth`. Текущие методы не ломаем.
- Новые методы: `/bots`, `/groups`, `/campaigns` (+ preview/test), `/records/route`.
- В `POST /records/add` поле `campaign_name`.
- Предпросмотр сообщения в Telegram сохранён.

### Что изменилось в 1.1

- Роли: **админ** и **сотрудник** (вместо оператора).
- Сотрудник: все запросы. Дашборд в v2.
- Админ: все запросы + дашборд в v2 + раздел админки Instagram/TikTok со вкладками.
- Вкладки админки: **Запросы** (только Instagram и TikTok), **Telegram** (боты и группы), **Рекламные кампании** (таблица TikTok и таблица Instagram).
- У статусов «не распределён» и «ошибка Telegram» — кнопка **Настроить**: бот, группа, заголовок.
- «Канал» заменён на **группу**. Шаблон сообщения заменён на **заголовок**.

## 1. Цель и границы

### 1.1. Цель

Собрать заявки с рекламы Instagram и TikTok, показать их в таблицах и отправить в Telegram боту и группе, привязанным к рекламной кампании. Общий список всех заявок (сайт + реклама) видят сотрудник и админ. Настройка маршрутов — только админ.

### 1.2. Входит в v1

- Редизайн общего списка всех заявок.
- Приём вебхуков Instagram и TikTok.
- Раздел админки со вкладками Запросы / Telegram / Рекламные кампании.
- CRUD ботов, групп, кампаний TikTok и Instagram (поля: бот, группа, заголовок).
- Кнопка «Настроить» для «не распределён» и «ошибка Telegram».
- Очередь отправки в Telegram с ретраями.

### 1.3. Вне скоупа v1

- Дашборд (версия 2, для обеих ролей).
- Создание рекламы внутри Meta / TikTok Ads Manager.
- Коллтрекинг, скоринг, WhatsApp / email / SMS.
- Публичный кабинет дилера.

### 1.4. Ключевое правило

Лид не теряется: при неизвестной кампании или ошибке Telegram заявка остаётся в таблице со статусом «не распределён» или «ошибка Telegram». Админ настраивает маршрут с кнопки в строке.

| Маршрут | Кампания → бот + группа + заголовок |

## 3. Роли

| Роль | v1 | v2 |
|---|---|---|
| Сотрудник | Общий список всех заявок, фильтры, отчёт | + дашборд |
| Админ | Всё как у сотрудника + раздел админки Instagram/TikTok (вкладки Запросы, Telegram, Рекламные кампании), сотрудники, интеграции | + дашборд |

## 4. Архитектура

Как в v1.0: вебхуки → API → PostgreSQL + очередь → Telegram Bot API в **группу**. Админка ходит только в API.

Рекомендуемый стек без изменений: React + NestJS/FastAPI + PostgreSQL + Redis.

---

## 5. Потоки данных

1. Человек отправляет форму в Instagram или TikTok (или заявку на сайте — в общий список без Telegram).
2. Рекламная платформа вызывает вебхук. Подпись проверяется.
3. Лид пишется в таблицу, дубль по `(source, external_lead_id)` отбрасывается.
4. Подбирается кампания: бот + группа + заголовок.
5. Сообщение уходит в группу. Статус: отправлено / не распределён / ошибка Telegram.

## 6. Таблицы запросов

### 6.1. Общий список (сотрудник и админ) — редизайн

Текущий экран: карточка «Фильтрация» (дата, бренд, сайт, тип запроса, UTM, имя, телефон, кто создал, Найти, сброс) и «Список заявок» (id, brand, site, тип, имя, телефон, дата, UTM, дилерский центр, скачать отчёт).

Редизайн сохраняет эти фильтры и колонки, добавляет:

- читаемые заголовки колонок (не обрезанные brand/site латиницей в шапке без пояснения);
- колонку **статус CRM** (новая / в работе / закрыта);
- нормальные отступы и выравнивание;
- пагинацию как сейчас.

Дашборд на этом экране не показывается.

### 6.2. Вкладка админки «Запросы» (только Instagram и TikTok)

Сайтовые заявки сюда не попадают.

| Колонка | Описание |
|---|---|
| Площадка | Instagram / TikTok |
| ID | внешний id |
| Имя, телефон, дилер | из формы |
| Кампания | campaign_name / Group Ads |
| Статус | отправлено / не распределён / ошибка Telegram / в очереди |
| Действие | кнопка «Настроить» |

### FR-11. Кнопка «Настроить»

Только у статусов **не распределён** и **ошибка Telegram**. Открывает панель кампании этого запроса:

- бот
- группа
- заголовок сообщения в Telegram

Сохранение пишет эти поля в рекламную кампанию и сразу повторяет отправку заявки. Если внутренней кампании нет — создаётся по внешнему id / Group Ads лида.

## 7. Поля Instagram

Источник — Instagram / Meta Lead Ads (Instant Forms). Состав ниже обязателен для отображения в таблице и карточке, если `platform = instagram`. Имена кастомных вопросов формы сохраняются в том виде, в каком их отдаёт Meta.

| Поле | Тип | Назначение |
|---|---|---|
| `id` | string | Идентификатор лида в Meta |
| `created_time` | datetime | Время создания заявки на стороне Meta |
| `ad_id` | string | ID объявления |
| `ad_name` | string | Название объявления |
| `adset_id` | string | ID группы объявлений |
| `adset_name` | string | Название группы объявлений |
| `campaign_id` | string | ID рекламной кампании Meta |
| `campaign_name` | string | Название кампании Meta |
| `form_id` | string | ID формы мгновенных ответов |
| `form_name` | string | Название формы |
| `is_organic` | boolean | Органическая заявка или рекламная |
| `platform` | string | Площадка, как отдаёт Meta (`instagram` / `fb`) |
| `выберите_автоцентр_dongfeng_ближайший_к_вам` | string | Выбранный автоцентр |
| `вы_обращаетесь_как_физическое_или_юридическое_лицо?` | string | Тип обращения |

| `номер_телефона` | string | Телефон лида |
| `lead_status` | string | Статус лида на стороне Meta |

### FR-20. Вебхук Meta

Подписка на `leadgen`. GET-верификация `hub.challenge`. POST проверяет `X-Hub-Signature-256`. По `leadgen_id` сервис забирает полный лид через Graph API (page token), включая `field_data` формы.

### FR-21. Нормализация Instagram

| Поле формы | Колонка сервиса |
|---|---|
| `полное_имя` | `name` |
| `номер_телефона` | `phone` |
| `выберите_автоцентр_dongfeng_ближайший_к_вам` | `dealer` |
| `вы_обращаетесь_как_физическое_или_юридическое_лицо?` | `person_type` |

Неизвестные вопросы складываются в `extra_fields` jsonb без потери. Полный ответ платформы — в `payload`.

## 9. Доставка в Telegram

Для каждой рекламной кампании админ выбирает бота, группу и заголовок. `sendMessage` от имени бота в `chat_id` группы. Бот — администратор группы с правом публикации.

### FR-40. Заголовок

Первая строка сообщения. Тело стандартное. Пустой заголовок допустим.

```
{заголовок}

Имя: {name}
Телефон: {phone}
Автоцентр: {dealer}
Площадка: {platform}
Кампания: {campaign_name}
ID: {external_lead_id}
```

### FR-41. Очередь

5 попыток (5 с, 20 с, 1 мин, 5 мин, 15 мин), учёт 429. После исчерпания — «ошибка Telegram».

### FR-42. Проверка

Бот: `getMe`. Группа: `getChat` + право отправки.

## 10. Рекламные кампании

Вкладка админки: **две таблицы** — TikTok и Instagram. CRUD: добавить / изменить / удалить.

| Поле | Обязательно | Описание |
|---|---|---|
| name | да | Имя кампании |
| platform | да | `instagram` или `tiktok` (определяется таблицей) |
| telegram_bot_id | да, если active | Бот |
| telegram_group_id | да, если active | Группа |
| message_title | нет | Заголовок сообщения |
| match_rules | да | Сопоставление с внешней РК |
| status | да | active / paused / archived |

Правила сопоставления без изменений: Instagram по campaign_id / adset_id / ad_id / form_id; TikTok по Group Ads / Ad name / Name Ads.

Удаление при наличии лидов — архивация. Нельзя активировать без бота и группы.

## 13. API

База: `https://notify-api.aps.by`. Документация: https://notify-api.aps.by/docs (`Notification_APS` 0.0.3). OpenAPI: `/openapi.json`.

Для всех методов, кроме `POST /users/login`, заголовок **`x-auth`**. Существующие методы не ломаем — расширяем в том же стиле (`/entity/add`, `PATCH /entity/update`, схемы `S*`, ответы `SSuccess` / `SError`, коды 403 / 409 / 422).

### 13.1. Уже есть

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/records/all_info` | Список заявок, тело `SAllRecordsInfo` |
| POST | `/records/file` | Выгрузка файла |
| GET | `/records/one?id=` | Одна заявка |
| POST | `/records/add` | Создать заявку, тело `SAddRecord` |
| PATCH | `/records/status` | Сменить статус |
| POST | `/callbacks/add` | Обратный звонок |
| POST | `/history/add` | История |
| GET / POST | `/brands`, `/brands/add` | Бренды |
| GET / POST | `/requests`, `/requests/add` | Типы запросов |
| GET / POST | `/sites`, `/sites/add` | Сайты |
| GET / POST | `/statuses`, `/statuses/add` | Статусы |

### 13.2. Доработка `POST /records/add`

В `SAddRecord` добавить поле:

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `campaign_name` | string или null | нет | Название рекламной кампании (Instagram `campaign_name` или TikTok `Group Ads`) |

Остальные поля `SAddRecord` без изменений: обязательные `request_id`, `site_id`; опционально `name`, `phone`, `email`, `comment`, согласия, `utm`, `vin`, `url`, `need_to_call_back`, `brand_id`, `date_call`, `info`.

После `add`: если `campaign_name` совпало с кампанией, у которой заданы бот и группа — заявка уходит в Telegram. Иначе статус «не распределён».

То же поле — необязательный фильтр в `SAllRecordsInfo`. В `SRecordInfoOne` отдать кампанию и статус доставки в Telegram.

### 13.3. Новые методы: боты

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/bots` | — | `SBot[]` без токена |
| POST | `/bots/add` | `SAddBot {name, token}` | `SSuccess`, внутри `getMe` |
| PATCH | `/bots/update` | `SUpdateBot {id, name?, token?, is_active?}` | `SSuccess` |
| POST | `/bots/delete` | `{id}` | `SSuccess` или 409, если бот в кампании |
| POST | `/bots/verify` | `{id}` или `{token}` | username, telegram_id |

### 13.4. Новые методы: группы

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/groups` | — | `SGroup[]` |
| POST | `/groups/add` | `SAddGroup {name, chat_id}` | `SSuccess` |
| PATCH | `/groups/update` | `SUpdateGroup {id, name?, chat_id?}` | `SSuccess` |
| POST | `/groups/delete` | `{id}` | `SSuccess` или 409 |
| POST | `/groups/verify` | `{id, bot_id}` | проверка `getChat` и права писать |

### 13.5. Новые методы: рекламные кампании

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/campaigns?platform=` | `instagram` или `tiktok` | `SCampaign[]` |
| POST | `/campaigns/add` | `{name, platform, bot_id, group_id, message_title?}` | `SSuccess` |
| PATCH | `/campaigns/update` | `{id, name?, bot_id?, group_id?, message_title?, is_active?}` | `SSuccess` |
| POST | `/campaigns/delete` | `{id}` | `SSuccess` или архивация |
| POST | `/campaigns/preview` | `{bot_id, group_id, message_title, name, phone, dealer, campaign_name}` | `{text}` — предпросмотр, в Telegram не шлёт |
| POST | `/campaigns/test` | как preview | тестовая отправка в группу |
| POST | `/records/route` | `{record_id, bot_id, group_id, message_title}` | кнопка «Настроить»: обновить РК и отправить заявку |

`SCampaign`: `id`, `name`, `platform`, `bot` (`SRecordItem`), `group` (`SRecordItem`), `message_title`.

Предпросмотр обязателен в форме кампании и в панели «Настроить». Данные — `POST /campaigns/preview`. «Отправить тест» — `POST /campaigns/test`.

Новые методы требуют `x-auth`. Сотрудник на `/bots`, `/groups`, `/campaigns`, `/records/route` получает 403.

## 16. Критерии приёмки v1

1. Текущие методы `/records/*`, `/users/*`, справочники работают как в `/docs`.
2. `POST /records/add` принимает `campaign_name` и маршрутизирует в Telegram.
3. CRUD ботов, групп, кампаний через новые методы. 409 при удалении занятого бота/группы.
4. `POST /campaigns/preview` возвращает текст и не пишет в Telegram. В UI есть пузырь предпросмотра.
5. Сотрудник видит общий список и не видит раздел админки Instagram/TikTok.
6. У «не распределён» / «ошибка Telegram» кнопка «Настроить» бьёт в `POST /records/route`.
7. Дашборд в v1 отсутствует.
